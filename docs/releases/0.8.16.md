RolidSCP is a fast two-panel file manager for local disks and remote servers over SFTP, inspired by WinSCP and Total Commander, written in Rust and native on Linux.

**This is a beta release.** It is used daily by its author, but expect rough edges. Please report bugs in Issues. Security problems should be reported privately, see [SECURITY.md](https://github.com/MrRolid/RolidSCP/blob/main/SECURITY.md).

## New in 0.8.16: big files and marking

### Marking as in other file managers

- **Shift+click** marks a range from the last clicked or marked item; **Shift with the arrows, Page Up, Page Down, Home and End** extends it, and going back unmarks only what that range marked.
- A **click without a key keeps the marks**; Ctrl+click toggles one item; **Ctrl+A** marks all and a second press unmarks. Insert and Space work as before. ".." is never marked, and Shift+click never starts moving files.
- Tools → **Select to the top / Select to the bottom** do the same as Shift+Home and Shift+End.
- The marks stay after a refresh, sorting and the quick filter; the start of a range is found again by name.

### What was tested, and how

**Honest note:** the test with a real file over 100 GB and the overnight transfer were planned for this release but were not finished. Real files were tested **only up to 2 GiB**; the full test moves to the next 0.8.x release (see the [roadmap](https://github.com/MrRolid/RolidSCP/blob/main/ROADMAP.md)).

- **Real, 2 GiB:** one file copied to a local SFTP server and back through the program's copy code, once canceled and once killed (SIGKILL) at half, both continued from the part file; every copy compared by SHA-256.
- **Simulated, terabytes to exabytes:** a synthetic data source whose content is computed instead of stored. Files of 1 TiB, 1 PiB, 8 EiB and the largest size a file can have resumed near the end, locally and to a server; counters, totals and the remaining time checked. A whole 1 TiB streamed through the copy code and verified byte by byte.
- **Full disk, real:** a small RAM disk filled in the middle of a transfer, on the local side and behind the local SFTP server. A **disk quota is simulated** (the error a quota gives).
- **Sparse files, real:** a 2 GiB file with 3 MB of data is copied correctly, but the holes are filled (the copy takes the full 2 GiB on disk).
- **Killed at random moments, 200 times:** copying and moving to and from a server, uploading an F4-edited file, packing, extracting, and saving the settings and the password vault.

The scripts are in [`scripts/bench`](https://github.com/MrRolid/RolidSCP/tree/main/scripts/bench). Measured on the author's machine (ext4, OpenSSH server on 127.0.0.1) while a CPU-heavy background job was running:

| | 0.8.16 | Limit |
|---|---|---|
| Ctrl+A in a folder of 1 000 000 files | 0.1 ms (0.8.15: about 0.7 s) | ≤ 200 ms |
| Shift+End over 1 000 000 files, with the footer | 48 ms | ≤ 50 ms |
| Longest frame in the window while marking all / Shift+End / Shift+Home | 3.0 / 13.8 / 13.5 ms | ≤ 50 ms |
| Refresh with all 1 000 000 marked, one file gone | 43 ms | |
| 2 GiB to the server / back, continued after a kill | 157 / 161 MB/s (`sftp put` 13 s, `get` 11 s for the whole file) | |
| Memory while copying 2 GiB | 16 MB, steady | |
| 1 TiB through the copy code (synthetic) | 892 s, 0 wrong bytes, counter never went back | |
| Full disk: message, older file kept, “Try again” finishes, no leftovers | up and down: yes | |
| Killed 200 times (172 really interrupted) | 0 damaged files, archives, settings or vaults; 0 lost sources; copies and moves continued with no leftovers | |

### Fixes

- **A full disk or a used-up quota** is named in the message, and “Try again” continues where the transfer stopped. A server that answers only “Failure” to a write gets a hint that its disk may be full or the quota used up.
- **A move continued after the program was killed** finishes: the files already complete in the target are moved too, their sources deleted only after the checksums match. A helper `.filepart-info` file left by a kill is cleaned up.
- After a lost connection the progress no longer counts the resumed part twice.
- The remaining time shows days (and “over 999 days”); sizes of petabytes and more are added up without overflowing.
- The journal of files being replaced on a server and the records of F4 copies are flushed to the disk, so a power cut cannot lose them.
- Shift+click and Ctrl+click are no longer missed when the key is released very quickly.

### Known problems

- The quick filter in a folder of a million files: the first key still makes one frame of about 0.3 s (limit 0.2 s), as in 0.8.15.
- Sparse files lose their holes when copied.
- A pack or extract killed in the middle leaves its unfinished `.filepart` file next to the archive or the extracted files (never a damaged archive or file); packing again under the same name replaces it, otherwise delete it by hand.

## Requirements

- Linux on 64-bit x86 (amd64 / x86_64) with glibc 2.35 or newer: Debian 12 and newer, Ubuntu 22.04 and newer, current Fedora, openSUSE Leap and Tumbleweed, or another distribution with the AppImage
- X11 session recommended (drag and drop to and from other applications is not available on Wayland)

## Install

Check the downloads with `sha256sum -c --ignore-missing SHA256SUMS`, then:

- Debian, Ubuntu, Linux Mint: `sudo apt install ./rolidscp_0.8.16_amd64.deb`
- Fedora: `sudo dnf install ./rolidscp-0.8.16-1.x86_64.rpm`
- openSUSE: `sudo zypper install --allow-unsigned-rpm ./rolidscp-0.8.16-1.x86_64.rpm`
- Other distributions: `chmod +x RolidSCP-0.8.16-x86_64.AppImage` and run it (needs FUSE)
