RolidSCP is a fast two-panel file manager for local disks and remote servers over SFTP, inspired by WinSCP and Total Commander, written in Rust and native on Linux.

**This is a beta release.** It is used daily by its author, but expect rough edges. Please report bugs in Issues. Security problems should be reported privately, see [SECURITY.md](https://github.com/MrRolid/RolidSCP/blob/main/SECURITY.md).

## New in 0.9.0: the settings window

The 0.9 series brings small new features, three to five in each release. This first one lays the ground for the rest: a window for the settings, which the later settings of 0.9 will go into.

### Settings in a window of their own

- **Settings → Settings…** or **Ctrl+,** opens the settings as a separate window, next to the main one. On the left is a tree of sections: Appearance (language and dates, font, panels, colors by file type, thumbnails), Files (copying and moving, archives), Tools (viewer, external editor) and Servers and security (server connections, saved passwords).
- **A field at the top finds a setting** in all the sections at once (**Ctrl+F**). It understands English and the language of the window, with or without accents, and also finds a setting by the name of its section and by related words.
- The settings that were spread over the Settings menu are in the window too: the speed limit, what F5 and dragging do with existing files, automatic refresh, the external editor and how soon saved passwords lock. The menu keeps its quick items; they are the same settings.
- **Save**, **Apply** and **Cancel**. A value out of range is marked in red and cannot be saved. Saving writes only what you changed in the window. What changed meanwhile, in the menus or in another window of the program, stays as it is.

### Duplicating a saved server

- **Duplicate…** under the list of saved servers makes a copy with all the settings of the server, under a new name ("Web (copy)", then "Web (copy 2)"…). The copy is selected, ready to be changed.
- When the server has a saved password, you choose whether the copy gets it too. By default it does not. Copying it needs the master password; when you do not enter it, the copy is made without the password and the window says so.

### Context menus by keyboard

- **Shift+F10** or the **Menu** key opens the menu of the file under the cursor, right next to it. On `..` or in an empty folder it opens the menu of the folder.
- **Ctrl+Shift+F10** or **Ctrl+Menu** opens the menu of the active tab: duplicate, rename, change the color, close, close the other tabs.
- The arrows move through the items, **→** opens a submenu, **Enter** picks, **Esc** closes. In the color palette **↓** or **Tab** goes through the colors, and the color in focus has a ring around it.
- Both are in the menu bar too (**File → Context menu of the item…**, **Settings → Tab menu…**), and in the list of keys under F1.

### A server whose clock is off

- After connecting, and after every reconnect, the program asks the server for its time with `date -u +%s`. It does so only where the server has a shell, and waits 5 seconds at most.
- When the server's clock is off by more than a minute, the line at the bottom says so once, the tooltip of the tab shows it, and the copy and move dialogs warn under "Overwrite only older". That choice compares the times of files, and a file changed on such a server carries the server's wrong time.
- The time the answer took is counted in: a slow line does not make a correct clock look wrong.
- A server without a shell, an answer that is not a number, a refused command or a lost connection give no warning at all. Tested against a real OpenSSH server whose clock was an hour ahead, one answering with a date in words, one with no shell, and a connection dropped before the question.
- The warning can be turned off in **Settings → Server connections**.

### Fixed

- **Two copies of the program could lose a server.** When both added or duplicated a server at the same moment, both servers could get the same id, and the merge of the shared `profiles.toml` (0.8.20) took them for one. The two-copies test before this release found it: of two servers duplicated in both windows at once, one was missing. Ids now carry a random part. The same test, run again three times, kept both servers every time.
- The AppImage is built the same way on every machine again. The file mode of the bundled licence texts depended on the build machine, and the build log now names the version of every bundled system library.

### Checked before the release

- **The program killed** (`kill -9`) at a random moment 200 times, while copying and moving to and from a server, uploading an F4 edit, packing, extracting and saving the settings and the saved passwords: nothing was lost or damaged.
- **A bad line:** transfers over a line with latency, jitter, 2 % and 5 % packet loss, a changing speed, short and long outages, a frozen connection and all of these at once. Every file arrived whole, checked by SHA-256.
- **Two copies of the program at once:** servers added and duplicated in both at the same moment (this found the bug above), and the settings window saving in one while the other changes other settings. Both copies' changes are kept.
- **Settings of older versions** are read without loss: the warning is on unless it was turned off. The one new value is written to the file only when you turn the warning off, and 0.8.20 keeps it when it saves, so going back and forth loses nothing.

## Requirements

- Linux on 64-bit x86 (amd64 / x86_64) with glibc 2.35 or newer: Debian 12 and newer, Ubuntu 22.04 and newer, current Fedora, openSUSE Leap and Tumbleweed, or another distribution with the AppImage
- X11 session recommended (drag and drop to and from other applications is not available on Wayland)

## Known problems

- A server that refuses a second SFTP channel gets folder listings through the library's own path, which has no limit on the number of entries.
- Sparse files lose their holes when copied.
- ACLs and extended attributes are not copied (planned for 0.9.5).
- A window of the program that is left alone takes the settings and servers saved by another running copy only at the next mouse move or key press. Nothing is lost: every save merges both.
- Not tested yet: a Windows server and a NAS.

## Install

Check the downloads first. With the release key (fingerprint `9B4B 4478 C213 BD34 3FC2  92C5 2EC7 4F7C CADB 33A2`), the signature and the checksums in one folder:

```sh
gpg --import release-key.asc
gpg --verify SHA256SUMS.asc SHA256SUMS
sha256sum -c --ignore-missing SHA256SUMS
```

- Debian, Ubuntu, Linux Mint: `sudo apt install ./rolidscp_0.9.0_amd64.deb`
- Fedora: `sudo dnf install ./rolidscp-0.9.0-1.x86_64.rpm`
- openSUSE: `sudo zypper install --allow-unsigned-rpm ./rolidscp-0.9.0-1.x86_64.rpm`
- Other distributions: `chmod +x RolidSCP-0.9.0-x86_64.AppImage` and run it (needs FUSE). The AppImage of 0.8.20 updates itself to this one with AppImageUpdate (`appimageupdatetool RolidSCP-0.8.20-x86_64.AppImage`).
