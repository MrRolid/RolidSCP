RolidSCP is a fast two-panel file manager for local disks and remote servers over SFTP, inspired by WinSCP and Total Commander, written in Rust and native on Linux.

**This is a beta release.** It is used daily by its author, but expect rough edges. Please report bugs in Issues. Security problems should be reported privately, see [SECURITY.md](https://github.com/MrRolid/RolidSCP/blob/main/SECURITY.md).

## New in 0.8.19: updates and real hardware

This release changes nothing in how the program works. It adds updates for the AppImage, and it brings the tests that needed a real second computer: a file of 110 GiB, a transfer through the night, a network cable pulled out and a server put to sleep.

### Updating the AppImage

- **The AppImage carries update information** (`gh-releases-zsync`), so [AppImageUpdate](https://github.com/AppImageCommunity/AppImageUpdate) and the tools built on it find a new release of RolidSCP on GitHub, pre-releases included, and download only the parts that changed. Suggested by the AppImage catalog.
- **Every release has its `.zsync` file**, listed in `SHA256SUMS` with the other files.
- Checked on every build: an older AppImage finds the update, and updating it gives the new AppImage byte for byte.
- In a terminal: `appimageupdatetool RolidSCP-0.8.19-x86_64.AppImage`. The new AppImage is saved next to the old one under the name of the release.

### Tested on a separate computer

A separate test machine with Linux Mint 22.3 on a 1 Gbit/s network, and the author's computer as the other side. The files are sparse files of pseudo-random data made for the test, so that 110 GiB fit on both disks; every copy was compared by SHA-256. The scripts are in [`scripts/bench`](https://github.com/MrRolid/RolidSCP/tree/main/scripts/bench) (`big-remote.sh`, `big.sh`, `overnight.sh`, `outage.sh`, `sparsefile.py`).

**A file of 110 GiB** (118 111 600 640 bytes), through the program's own copy code. Upload over the network from the author's computer; download on the test machine from its own SSH server, because only its disk holds the file twice. Each copy is stopped at half once by Cancel and continued with Resume, and once by killing the process (SIGKILL) and continued by a new process from the part file.

| 110 GiB | First half | Second half | Continued from | Remaining time at half, error | Memory | Open files | SHA-256 |
|---|---|---|---|---|---|---|---|
| Up, Cancel and Resume | 707 s (84 MB/s) | 757 s (78 MB/s) | the part file, byte for byte | 3.4 % | 18 MB | 9 | equal |
| Up, killed, new process | 511 s (116 MB/s) | 504 s (117 MB/s) | the part file less 2 MiB | 0.04 % | 16 MB | 9 | equal |
| Up, OpenSSH `sftp put` | 1020 s in all (116 MB/s) | – | – | – | – | – | equal |
| Down, Cancel and Resume | 309 s (191 MB/s) | 288 s (205 MB/s) | the part file, byte for byte | 19 % | 16 MB | 9 | equal |
| Down, killed, new process | 311 s (190 MB/s) | 287 s (205 MB/s) | the part file | 3.9 % | 17 MB | 9 | equal |

The counter of transferred bytes never went backwards, and no open file was left after a copy. In the first upload some minutes ran at only 30 MB/s; the two runs after it ran at the full speed of the line all the time, as `sftp` did.

**A transfer through the night**, in the program's real window: 100 GiB uploaded at the speed limit of 4 MiB/s set in the program, from 2:04 to 9:11.

| Hour | Transferred | Memory (RSS) | Threads | Open files |
|---|---|---|---|---|
| start | 0 | 184 MB | 111 | 20 |
| 1 | 15 GB | 223.70 MB | 111 | 20 |
| 4 | 60 GB | 223.79 MB | 112 | 20 |
| 7 | 106 GB | 223.88 MB | 112 | 20 |

It took 7 h 8 min (25 660 s) and kept the speed limit exactly. The memory grew by 0.18 MB in 7 hours, the number of open files did not change, the copy was equal, and the log shows no error and no reconnection.

**A network cable pulled out and a server put to sleep**, by hand at the test machine, in the program's real window: a file of 6 GiB on the way, the outage when a fifth of it had arrived. The program was not touched during the test.

| Outage | Way | Transfer stood still | Loss noticed | Connected again after the test machine answered | Whole transfer | SHA-256 |
|---|---|---|---|---|---|---|
| Cable out for 30 s | up | 45 s | after 15 s | within 3 s (3 attempts) | 813 s | equal |
| Cable out for 30 s | down | 2 min 37 s | after 15 s | within 3 s (22 attempts) | 924 s | equal |
| Cable out for 5 min | up | 8 min 34 s | after 15 s | 7 s (77 attempts) | 1289 s | equal |
| Cable out for 5 min | down | 7 min 29 s | after 15 s | 2 s (63 attempts) | 1984 s | equal |
| The test machine put to sleep and woken | up | 5 min 4 s | after 16 s | 2 s (56 attempts) | 1841 s | equal |

The test machine needed 2 to 3.5 minutes after the cable was plugged in again before it answered on the network, so the outages lasted longer than the cable was out. The program gave no error, did not stop the queue and needed no click; the log shows no error.

**The AppImage of 0.8.18 on the real Linux Mint**, started by an ordinary user without installing it: logging in to a server, a download and an upload compared by SHA-256, a new folder, packing onto the server, deleting; all steps passed, no error in the log.

## Requirements

- Linux on 64-bit x86 (amd64 / x86_64) with glibc 2.35 or newer: Debian 12 and newer, Ubuntu 22.04 and newer, current Fedora, openSUSE Leap and Tumbleweed, or another distribution with the AppImage
- X11 session recommended (drag and drop to and from other applications is not available on Wayland)

## Known problems

- A server that refuses a second SFTP channel gets folder listings through the library's own path, which has no limit on the number of entries.
- On a system without any fonts, a few symbols of the window (the sort arrow, the plus of the tabs, the disk and info signs) are missing; planned for 0.8.20.
- Sparse files lose their holes when copied.
- Early in a transfer whose speed changes, the remaining time can be far off (at a tenth of the 110 GiB upload it showed three times the real time); at half it was within 4 % in three of the four runs.
- Not tested yet: a Windows server and a NAS. X11 against Wayland, high-DPI screens, ACLs, extended attributes, time zones and the rest of the polish planned before have moved to 0.8.20 (see the [roadmap](https://github.com/MrRolid/RolidSCP/blob/main/ROADMAP.md)).

## Install

Check the downloads with `sha256sum -c --ignore-missing SHA256SUMS`, then:

- Debian, Ubuntu, Linux Mint: `sudo apt install ./rolidscp_0.8.19_amd64.deb`
- Fedora: `sudo dnf install ./rolidscp-0.8.19-1.x86_64.rpm`
- openSUSE: `sudo zypper install --allow-unsigned-rpm ./rolidscp-0.8.19-1.x86_64.rpm`
- Other distributions: `chmod +x RolidSCP-0.8.19-x86_64.AppImage` and run it (needs FUSE); later updates with AppImageUpdate
